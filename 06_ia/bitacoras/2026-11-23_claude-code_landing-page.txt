> Can this be uploaded to cloudflare pages? or not due to depending on python

● Yes, the page itself can go on Cloudflare Pages as is. The Python backend
  can't, though, because Pages serves static files and doesn't run a Flask
  server. The only part that needs replacing is the email endpoint.

  Uploads unchanged: index.html plus everything in assets/. The page has no
  build step and loads nothing from external hosts. The largest file is the
  7.3MB hero PNG, which is under Pages' 25MB per-file limit. Browsers actually
  load the 490KB JPEG instead.

  What replaces server.py: a Pages Function, which is a small JavaScript file at
  functions/api/preregistro.js. Cloudflare runs it automatically at the same
  /api/preregistro URL the form already posts to, so the page's code doesn't
  change. It would:
  - Validate the email and normalize it (trim and lowercase), the same as the
    Python version.
  - Check for duplicates and store new emails.
  - Return the same {ok, duplicate} JSON, so the existing success and error
    messages keep working.

  Where the emails go: Pages has no file system to append a CSV to. You'd bind
  one of these:
  - D1, Cloudflare's SQLite database. I'd recommend it: a single table with a
    unique email column handles duplicates for you. You can export the list as
    CSV from the dashboard or with wrangler d1 export.
  - KV, a key-value store with the email as the key. It's simpler, but listing
    and exporting all entries is clunkier.

  What you'd do on Cloudflare (a few minutes):
  1. Create the D1 database.
  2. Bind it to the Pages project under the name the function expects.
  3. Deploy the landing/ folder, either from Git or with wrangler pages deploy
     landing.

  server.py can stay as the local development option, or be removed if you only
  deploy to Cloudflare.

  Want me to write the Pages Function and the D1 table schema? I'd also add the
  deploy steps to the project.
